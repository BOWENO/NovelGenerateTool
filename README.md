# NovelGenerateTool

本地小说创作桌面工具，版本0.1.0。支持书架、编辑器、分卷与章节规划、人物和设定资料、写作助手、拆书、定向修订和历史恢复。

新章先成为草稿。审查建议与作者采用分别记录，采用后核对正文版本并交接资料，再生成下一章。关闭应用后可以恢复待审稿；草稿修改后需更新审查建议。

## 启动与构建

需要 Node.js 22及npm。在本目录执行：

```bash
npm ci
npm run dev
```

已有源码构建可用 `npm run preview` 启动。首次打开“设置 → AI服务”，配置服务商与模型。未配置服务商时不会生成正文；模型调用直连所配置的服务商，其费用由该服务商决定。

```bash
npm test
npm run typecheck
npm run build
npm run dist:linux
npm run dist:win
npm run dist:win:portable
```

Linux命令生成 `release/linux-unpacked/`，运行其中的 `novelgeneratetool`。Windows便携命令生成 `release/win-unpacked/`，运行其中的 `NovelGenerateTool.exe`；程序依赖同目录其他文件，请完整保留目录。

0.1.0已在Linux桌面验证启动、待审稿重启恢复、采用及章节进度；Windows便携目录已构建，尚未在Windows运行。`dist:win`用于生成安装包，本次Linux构建环境缺少Wine，安装包未完成。跨平台便携构建跳过Windows签名及可执行文件元信息定制。

## 本次改造

- 界面、包名、应用ID、数据前缀、主题、图标统一命名；移除原更新源和营销材料。
- 生成、审查和采用固定书籍；切书停止在途生成，写盘前再校验。
- 已有章节按实际正文审阅；资料登记读取作者实际采用的文本，并记录来源文件和摘要值。来源变化则拒绝登记。
- 本书及全局记忆、伏笔和上一章原文完整保留。输入超过模型可用容量时明确停止，保留资料。
- 角色卡内部的性格、经历子标题保留在同一张卡中。
- 模型长度截断、异常响应和缺少结束标记均不视为完整结果。
- 会话压缩后再构造发送历史；不将已压缩旧原文重复带入当轮。
- 状态扫描仅核对登记章节之后的文本，不把最新死亡状态用于判断此前正常出场。
- 文本检查提供统计与待核查提示，移除人类信号评分、检测概率和写作配额。文学判断仍需连读与实际反馈。
- 正文、元信息、核心资料、记忆与配置通过同目录临时文件替换保存，采用稿时检查冲突；AI记忆修改也通过提案审阅。

## 数据

应用配置默认位于系统应用数据目录的 `NovelGenerateTool/`。书架默认位于文档目录的 `NovelGenerateTool 书架/`，可在设置中改变。每本书包含正文、草稿、大纲、角色、设定、资料JSON、审查报告和历史快照。

开发或隔离测试可设置 `NOVELGENERATETOOL_DATA_DIR` 为绝对目录，此时测试书架也放在该目录中。不要将测试目录设置为正在使用的书架。

原小说项目和其生产线仍使用原文件，本工具的开发不会自动导入或采用那些候选稿。

Linux隔离桌面验证可运行 `node scripts/smoke.cjs`，需要Xvfb和已构建的Linux包。输出目录可用 `NOVELGENERATETOOL_SMOKE_OUTPUT` 指定；默认使用临时目录，测试不会连接真实模型。
